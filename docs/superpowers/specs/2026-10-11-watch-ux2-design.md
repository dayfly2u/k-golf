# K-Golf 워치 UX2.0 리디자인 — 설계

- 작성일: 2026-10-11
- 대상: `wear` 모듈(워치 앱) + 폰↔워치 통신(`WearSync`, `RoundRecordingService`)
- 기준 시안: `docs/design/2026-10-redesign/WatchIdle.dc.html`(대기), `WatchPlay.dc.html`(홀 기록), `WatchHole.dc.html`(홀 이동)
- 상위 문서: 폰 리디자인 스펙 `docs/design/2026-10-redesign/redesign-spec.md`(이 문서는 워치 부분만 다룸)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this spec task-by-task, via an implementation plan generated by superpowers:writing-plans.

**Goal:** 지금은 기본 Wear Compose 버튼과 텍스트로 된 워치 화면을, 확정된 원형 시안(진행 링, 큰 숫자, 이 홀 결과/합계, 홀 이동 요약)으로 교체한다. 워치에서 하던 일(타수 ±, 홀 이동, 폰 연결/GPS 안내)은 그대로 유지한다.

## 1. 결정 사항 (브레인스토밍 결과)

| 항목 | 결정 |
|---|---|
| 홀 이동 화면 | ◀/▶를 누르면 **홀이 즉시 바뀌고**, 그 직후 이 화면이 2~3초 떴다가 자동으로 홀 기록으로 돌아간다. 화면을 탭하면 바로 돌아간다. |
| 글꼴 | 큰 숫자만 시안의 **Barlow Condensed**(wear 모듈에 번들, 약 0.3MB). 한글 라벨은 워치 시스템 글꼴(IBM Plex Sans KR은 굵기당 2.8MB라 제외). |
| 강조 녹색 | 시안 기본값 `#2E7D4F`(검정 바탕에서 폰의 `FieldGreen #1F5C3F`보다 잘 보이는 밝은 녹색). 노랑은 폰과 같은 `#F2C14E`. |
| 합계 0 표기 | 시안 로직대로 `0`(폰 화면의 "E"와 다름). 양수 `+5`, 음수 `-2`. |

## 2. 화면 (원형, 시안 360 기준을 화면 크기에 비례해 확대·축소)

### 2.1 대기 (`WatchIdleScreen`) — 라운드가 없을 때
- 검정 바탕, 가운데에 64 둥근 사각 녹색 로고(깃발 선 아이콘) + "K-Golf"(20, 700) + "폰에서 라운드를 시작하면\n여기에 홀이 표시돼요"(14, `#C9D1CB`).
- 아래쪽 작은 안내 "연결되면 자동으로 따라와요"(11, `#7E8A82`).
- 폰 연결이 끊겨 있으면 위쪽에 호박색 알약 "폰 연결 끊김"(배경 `#3A2A0E`, 글자 `#F2C14E`, 연결 끊김 아이콘).

### 2.2 홀 기록 (`WatchPlayScreen`) — 라운드 진행 중
- **진행 링**: 테두리를 따라 홀 수만큼 칸(18홀이면 18칸, 칸 사이 틈 4/360). 지나온 홀=강조 녹색, 현재 홀=`#F2C14E`, 남은 홀=`#26332B`. 12시 방향에서 시작.
- 맨 위 연결 상태 줄: 연결되면 `● 폰 연결됨`(11, `#9AA59C`, 점 `#4CAF50`), 끊기면 호박색 "폰 연결 끊김" 알약, GPS 실패 때는 진동 + "GPS 신호 없음"을 같은 줄에 2.5초 표시.
- 가운데 위: `[◀ 44] HOLE 7 / [파 4] [▶ 44]` — 번호는 Barlow 30 Bold, 파 칩은 `#F2C14E` 바탕 검정 글자. ◀는 1홀에서, ▶는 마지막 홀에서 비활성.
- 두 줄 스테퍼: `그린까지`, `숏 · 퍼팅` — 각 줄 `[− 52 원형 #1E2A22] 라벨(11, #9AA59C) + 값(Barlow 46 Bold) [+ 52 원형 강조 녹색]`. 값 0에서 −는 비활성(기존과 같음).
- 맨 아래: `이 홀 {타수}타 · {등급}`(13, 600; 타수는 Barlow 17)과 `합계 {합계}`(11; 값은 Barlow 14 흰색).
  - 이 홀 타수 = `그린까지 + 숏·퍼팅`(폰이 이미 숏어프로치+퍼팅을 합쳐 보낸다).
  - 등급 = 이 홀 타수 − 파: -3 앨버트로스, -2 이글, -1 버디, 0 파, 1 보기, 2 더블, 3 트리플, 그 밖은 `+4`/`-4`처럼 부호 숫자. 이 홀 타수가 0이면 `이 홀 0타 · -`.
  - 합계 = `scoreBefore`(현재 홀 이전까지의 파 대비 합) + (이 홀 타수 > 0 ? 이 홀 파 대비 : 0).

### 2.3 홀 이동 (`WatchHoleScreen`) — 홀이 바뀐 직후
- 링은 새 홀 기준으로 갱신(시안: 8번 홀 이동 → 7칸 녹색 + 8번째 노랑).
- 위에 "다음 홀로 이동"(12, `#9AA59C`) — ◀로 이동했으면 "이전 홀로 이동". 가운데 큰 `HOLE`(22) + 번호(Barlow 96 Bold) + 파 칩. 양옆에 56 원형 ◀(어두운 `#1E2A22`) / ▶(강조 녹색). 누르면 같은 방식으로 홀이 또 바뀌고 표시 시간이 처음부터 다시 센다.
- 아래: `{n-1}번 홀 {타수}타 · {등급}`과 `합계 {scoreBefore}`. 이전 홀 기록이 없으면(1번 홀, 건너뜀) 첫 줄을 생략한다.
- 이 화면은 **워치에서 ◀/▶를 눌러 홀이 바뀐 경우에만** 뜬다(폰에서 홀이 바뀐 경우는 조용히 홀 기록 화면만 갱신).

## 3. 폰 ↔ 워치 통신 변경

`WearSync.kt`는 `app`과 `wear`에 복제본이 있어 **두 파일을 같이 고친다**(주석에 이미 명시된 규칙). 새 키는 모두 선택값이라, 한쪽만 구버전이어도 동작한다.

| 키 | 타입 | 의미 |
|---|---|---|
| `scoreBefore` | Int | 현재 홀보다 번호가 작은 홀 중 **타수가 1 이상인 홀**의 (타수 − 파) 합. 해당 홀이 없으면 0 |
| `prevHoleStrokes` | Int | 바로 이전 홀(현재 번호 − 1)의 총타수. 그 홀의 타수가 0이면 **키를 보내지 않음** |
| `prevHolePar` | Int | 그 홀의 파 (`prevHoleStrokes`와 함께만 보냄) |

- 폰 `RoundRecordingService.pushState`에서 계산한다. **홀별 타수는 `hole_records`가 아니라 샷·벌타 기록에서 구한다** — `hole_records`는 폰 라운드 화면이 열려 있을 때만 저장되는데, 워치로만 기록하는 동안에는 이 서비스만 살아 있기 때문이다. 방법: `shotRepository.getShotsForRound` + `penaltyRepository.getPenaltiesForRound`를 한 번 읽어 홀별로 `StrokeCalculator.currentTotal`(TO_GREEN + SHORT_GAME + PUTT; 벌타 포함, 워치에 이미 표시되는 값과 같은 기준)을 합산한다. 파는 `pushState`가 이미 읽는 코스 홀의 파를 쓰고, 코스에 없는 홀 번호는 기존과 같이 4로 본다.
- 계산은 순수 함수(`domain/model`의 새 파일, 입력: 홀별 파 맵·샷 목록·벌타 목록·현재 홀 번호 → 출력: `scoreBefore`와 이전 홀 결과)로 분리해 JVM 단위 테스트로 검증한다.
- 워치 `RoundUiState`에 `scoreBefore`, `prevHole`(없으면 null)을 추가하고 `applyDataMap`에서 읽는다. 키가 없으면 `scoreBefore = 0`, `prevHole = null`.

## 4. 워치 코드 구조 (`wear/src/main/kotlin/com/golfrecorder/wear/`)

| 파일 | 역할 |
|---|---|
| `MainActivity.kt` | 상태에 따라 세 화면 중 하나를 그리는 라우터 + 기존 진동·권한·GPS 서비스·연결 안내 로직(동작 유지) |
| `WatchIdleScreen.kt`, `WatchPlayScreen.kt`, `WatchHoleScreen.kt` | 화면별 Composable |
| `WatchRing.kt` | 진행 링(Canvas) |
| `WatchTokens.kt` | 시안의 색(`#000`, `#1E2A22`, `#26332B`, `#F2C14E`, `#2E7D4F`, `#9AA59C`, `#4CAF50`, `#3A2A0E` …)과 Barlow 글꼴 |
| `WatchScale.kt` | 시안 360 기준 → 실제 화면 배율 + 글자·터치 영역 하한(아래 참고) |
| `WatchComponents.kt`, `WatchIcons.kt`, `WatchStatus.kt` | 공용 부품: 원형 버튼, 파 칩, 합계 줄, 아이콘(깃발·쉐브론·Wi-Fi 끊김), 연결 상태 줄/알약 |
| `HoleMoveOverlay.kt` | 홀 이동 화면 표시 상태 홀더(타이머 포함, 단위 테스트 대상) |
| `RoundDisplay.kt` | 순수 로직: 등급 이름, 합계/이 홀 문자열, 링 칸 상태, 연결 배지 우선순위 |
| `res/font/barlow_condensed_*.ttf` | 숫자 글꼴(폰 앱 것을 복사) |

- **화면 배율과 하한:** `BoxWithConstraints`로 `factor = min(폭, 높이) / 360`을 구해 도형·간격·위치에 곱한다. 대상 워치(SM-R900)는 396×396px, 320dpi라 **198×198dp → factor 0.55**이고, 시안의 글자·버튼을 그대로 곱하면 11px 라벨이 약 6sp, 52px 버튼이 약 29dp가 되어 읽거나 누르기 어렵다. 그래서 **글자는 역할별 최소 크기(기본 10sp), 눌러야 하는 원형 버튼은 최소 34~38dp**를 두고 나머지는 비례로 둔다. 세로 배치는 시안의 절대 위치 대신 `SpaceBetween` 열로 두어 남는 간격을 고르게 나눈다. 수치는 `WatchScale`과 각 화면 파일 상단 상수에 모여 있어, 실기기 확인 후 한 곳에서 조절한다.
- 통신·낙관적 표시·GPS 서비스(`RoundStateViewModel`, `WatchLocationService`)는 새 필드 읽기 외에는 바꾸지 않는다.
- 홀 이동 화면 표시 상태는 `HoleMoveOverlayState`(Compose 상태 + 코루틴 타이머)가 맡는다. ◀/▶를 누르면 "이동 요청"이 서고(5초 뒤 자동 해제), 이후 `holeNumber`가 바뀌면 화면을 2.5초 보여준 뒤 끈다. 이동 화면이 떠 있는 동안 홀이 또 바뀌면(연속 이동 포함) 타이머를 처음부터 다시 센다.
- 의존성: 별도 네비게이션 라이브러리는 쓰지 않는다. wear 모듈에 `testImplementation`으로 `libs.junit`, `libs.kotlinx.coroutines.test`만 추가.

## 5. 상태·예외 처리
- 연결 끊김: 대기/기록 두 화면 모두 호박색 알약. 끊긴 동안 눌러도 기존처럼 큐에 쌓이고 숫자는 낙관적으로 바로 바뀐다.
- 다시 연결: 알약이 `● 폰 연결됨` 줄로 돌아간다(기존의 2.5초 "재연결" 문구는 없앰).
- 라운드 종료/미시작: 어느 화면이든 대기 화면으로.
- 홀 번호가 바뀌면 이전 홀 기준 낙관적 증감분을 지우는 기존 동작 유지.

## 6. 테스트·검증
- 단위 테스트(wear): `RoundDisplay`의 등급 이름(-3~+3, 범위 밖), 합계 문자열(양수/0/음수), 이 홀 0타 처리, 링 칸 상태(18홀/9홀, 첫 홀/마지막 홀).
- 단위 테스트(app): `scoreBefore`, 이전 홀 결과 계산(벌타 포함, 타수 0인 홀 제외, 코스에 없는 홀 번호는 파 4, 이전 홀 타수 0이면 이전 홀 결과 없음, 1번 홀).
- 빌드: `:app`, `:wear` 둘 다.
- 화면 확인은 사용자가 워치 실기기에서 한다(그라운드룰). 워치 설치 시 adb는 항상 `-s <워치 시리얼>`을 명시한다.
