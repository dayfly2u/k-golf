## 1. 디자인 토큰 (`ui/theme/GolfTokens.kt`)

Material3의 `ColorScheme`(primary/secondary 같은 고정 역할)에 억지로 끼워맞추지 않고, 평범한 Kotlin `object`로 선언한다 — 이 프로젝트는 테마 프로바이더 없이 화면마다 `MaterialTheme.typography`/직접 `Color(0xFF...)`를 섞어 쓰는 컨벤션이라, `object` 하나가 가장 적은 구조 변경으로 "색상 드리프트" 문제를 없앤다(이번 세션에 실제로 경고 배지 색이 행 배경과 겹쳐 안 보이는 버그가 분산된 색상 상수 때문에 두 번 발생했음).

```kotlin
object GolfTokens {
    // 기본
    val FieldGreen = Color(0xFF1F5C3F)
    val FieldGreenDark = Color(0xFF123A28)
    val Accent = Color(0xFFF2C14E) // CTA, 현재 홀
    val Background = Color(0xFFF4F5EF)
    val CardBackground = Color(0xFFFFFFFF)

    // 텍스트
    val TextPrimary = Color(0xFF18241D)
    val TextSecondary = Color(0xFF56635A)
    val Divider = Color(0xFFECEFE7)
    val Border = Color(0xFFCDD3C8)

    // 벌타
    val ObBackground = Color(0xFFFFF6E8)
    val ObBorder = Color(0xFFE3A34A)
    val ObText = Color(0xFF7A4A0C)
    val HazardBackground = Color(0xFFEEF3F9)
    val HazardBorder = Color(0xFF6B8FB8)
    val HazardText = Color(0xFF24476E)

    // 스코어 셀(파 이하/보기/더블 이상) — 스코어카드 그리드·홈 배지 공용
    val ScoreUnderParBorder = Border // 흰 바탕 + 테두리
    val ScoreBogeyBackground = Color(0xFFDCE6F1)
    val ScoreDoubleOrWorseBackground = Color(0xFF6B8FB8) // 흰 글자

    // 모서리
    val CardCorner = 20.dp   // 18~22dp 범위 중앙값
    val ButtonCorner = 16.dp // 14~18dp 범위 중앙값
    val ChipCorner = 999.dp

    // 터치 영역
    val MinTouchTarget = 44.dp
    val PrimaryButtonHeight = 58.dp
}

// res/font에 번들된 Google Fonts(OFL) 두 개
val BodyFontFamily = FontFamily(Font(R.font.ibm_plex_sans_kr_regular, FontWeight.Normal), ...)
val NumberFontFamily = FontFamily(Font(R.font.barlow_condensed_medium, FontWeight.Medium), ...) // 스코어/타수/거리/통계 숫자 전용
```

- 홈 화면 점수 배지는 **현재 구간 기준(80대/90~94/95~99/100+) 유지** — 색상 값만 위 팔레트로 교체(파랑→`#6B8FB8` 계열, 초록→`FieldGreen` 계열, 연한빨강/진한빨강→시안의 보기/더블 색 재사용). 시안의 베스트/양호/보통 3단계 예시는 채택하지 않는다.
- 이모지 아이콘(🔍, ✏️, ≡ 텍스트)은 전부 벡터(`ImageVector`/`painterResource`)로 교체.

## 4. 스테이지 3 — 신규-UI (기존 데이터로 계산/표시만 추가, 스키마 변경 없음)

### 4.1 GIR/L-GIR 이름 교체
`HoleResult.isGreenInRegulation`(strokesToGreen만 판정)이 표시상 **"L-GIR"**, `isStrictGreenInRegulation`(숏어프로치 없음까지 확인)이 표시상 **"GIR"**로 바뀐다. 코드 레벨 프로퍼티/변수명(`isGreenInRegulation`, `isStrictGreenInRegulation`, `strictGirCount` 등)은 그대로 두고 **UI 라벨 문자열만** 바꾼다 — 의미를 바꾸는 리네이밍이 아니라 표시 교체이므로 혼동 방지를 위해 라벨 변경 지점(`GirSummaryLines`, `RoundSummaryScreen`의 6칸 그리드)에 주석으로 "코드명과 표시명이 반대" 사실을 남긴다.
적용 범위: 결과 화면 6칸 통계, 홈 화면 펼침의 GIR 줄(기존 `GirSummaryLines` 공용 컴포넌트) 전부.

### 4.2 결과 화면 6칸 통계 + 홀 결과 비율 막대
- 6칸: GIR, L-GIR, 퍼팅(합계·홀당 평균), 드라이버 평균, 드라이버 최장, 벌타(OB/해저드 합) — 전부 기존 `HoleResult`/`DriverDistanceStats`/`PenaltyRepository` 데이터로 계산, 새 쿼리 불필요.
- 홀 결과 비율: 18홀을 버디 이하/파/보기/더블/트리플+ 5구간으로 분류(`scoreToPar` 기준, 기존 `scoreRowColor` 분기 로직 재사용)해 하나의 가로 막대에 비율로, 아래 범례에 홀 수.

### 4.3 홈 상단 요약 + 스코어 뱃지 파 대비
- 상단 3칸: 전체 라운드 평균 스코어, 베스트 스코어, 평균 퍼팅(전체 라운드 기준 — `RoundRepository.getRoundSummaries()`에 집계 쿼리 추가 또는 클라이언트에서 전체 리스트 합산, 라운드 수가 적어 클라이언트 합산으로 충분).
- 각 라운드 카드 배지에 파 대비(`+22` 등) 작게 추가.

### 4.4 "최근 5회 중 N위" 뱃지
라운드 결과 화면 헤더에 표시. **판단**: 코스 무관 전체 라운드 기준, `playedAt` 내림차순 최근 5개(지금 보는 라운드 포함) 중 `totalStrokes` 오름차순 순위. 동률이면 더 최근 라운드가 높은 순위. 전체 라운드가 5개 미만이면 "최근 N회 중 M위"로 모수를 그대로 표기.

### 4.5 18홀 진행바 + 현재 스코어 (`RoundPlayScreen` 라이브)
- `HoleProgressBar`: 완료 홀(`holeNumber < currentHoleNumber`)=`FieldGreen`, 현재 홀=`Accent`, 남은 홀(`holeNumber > currentHoleNumber`)=연회색.
- 현재 스코어: **진행 홀까지**(지나온 홀만, 지금 치는 홀 제외)의 파 대비. **주의**: `RoundPlayViewModel.loadHole()`이 홀에 들어오는 즉시(한 타도 안 쳤어도) `hole_records`에 그 홀을 반영해두므로(`strokesToGreen=0`인 채로도 upsert됨 — 결과 화면에 빈 홀이 바로 보이게 하기 위한 기존 설계), "`hole_records`에 저장됐는지"로는 현재 홀을 걸러낼 수 없다. `holeResults.filter { it.holeNumber < viewModel.currentHoleNumber }.sumOf { it.scoreToPar }`처럼 **홀 번호 비교로 명시적으로** 현재 홀을 제외해야 한다.
- 다음 홀 버튼의 "이 홀 N타 · 등급" 서브텍스트는 저장 전 현재 홀의 실시간 스테퍼 값(`strokesToGreen + strokesShortGame + strokesPutt`)으로 계산 — ViewModel이 이미 들고 있는 상태 재사용.

### 4.6 18홀 진행바 (`RoundPlayScreen` isReview, 홀 상세)
완료된 라운드이므로 "남은 홀" 개념이 없다 — 지금 보는 홀만 `Accent`, 나머지 17홀은 전부 `FieldGreen`(시안 `Hole.dc.html` 그대로). `HoleProgressBar`에 `mode: Live | Review` 파라미터로 분기.

### 4.7 그린까지 거리 오버레이
기존에 이미 계산되는 "그린까지 거리"(현재는 오프라인일 때만 텍스트로 노출)를 온라인 포함 항상 지도 위 좌상단 오버레이로 표시. 데이터는 이미 있으므로 `CourseMapView`에 오버레이 UI만 추가.

## 5. 스테이지 4 — 신규-데이터

### 5.1 코스 난이도 0.5 단위 (`courses.difficulty: Int?` → `Double?`)

- **평점**(`rating`)은 이미 `Double?`이라 UI만 바꾼다(−/+ 0.5 버튼, 별 반 개 표시).
- **난이도**는 타입 자체가 바뀌므로 마이그레이션 필요. SQLite는 컬럼 타입을 직접 바꿀 수 없어 `C:\github\k-golf\CLAUDE.md`의 "임시 테이블 생성 → 데이터 복사 → 기존 테이블 삭제 → rename" 패턴을 쓴다:

`app/schemas/com.golfrecorder.data.local.AppDatabase/19.json`의 `courses` 테이블 전체 컬럼(인덱스 없음, 외래키 없음):

```
id INTEGER PK AUTOINCREMENT NOT NULL, name TEXT NOT NULL, holeCount INTEGER NOT NULL,
createdAt INTEGER NOT NULL, sortOrder INTEGER NOT NULL, rating REAL, difficulty INTEGER,
region TEXT, distance TEXT, travelTime TEXT, oneLineReview TEXT, transportInfo TEXT,
clubhouseInfo TEXT, courseInfo TEXT
```

```kotlin
val MIGRATION_19_20 = object : Migration(19, 20) {
    override fun migrate(db: SupportSQLiteDatabase) {
        db.execSQL(
            """
            CREATE TABLE courses_new (
                id INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
                name TEXT NOT NULL,
                holeCount INTEGER NOT NULL,
                createdAt INTEGER NOT NULL,
                sortOrder INTEGER NOT NULL,
                rating REAL,
                difficulty REAL,
                region TEXT,
                distance TEXT,
                travelTime TEXT,
                oneLineReview TEXT,
                transportInfo TEXT,
                clubhouseInfo TEXT,
                courseInfo TEXT
            )
            """
        )
        db.execSQL(
            """
            INSERT INTO courses_new
            SELECT id, name, holeCount, createdAt, sortOrder, rating, CAST(difficulty AS REAL),
                   region, distance, travelTime, oneLineReview, transportInfo, clubhouseInfo, courseInfo
            FROM courses
            """
        )
        db.execSQL("DROP TABLE courses")
        db.execSQL("ALTER TABLE courses_new RENAME TO courses")
    }
}
```

- `CourseEntity.difficulty: Int?` → `Double?`, `CourseDao`/`CourseRepository`의 관련 시그니처 전부 `Double?`로.
- `CourseManageScreen`의 "난이도 N" 표시, `CourseEditScreen`의 입력 UI(−/+ 0.5, 막대 반 칸)를 `rating`과 동일한 패턴으로 구현.
- 기존 정수 난이도 값은 `x.0`으로 보존 확인(실기기 업그레이드 경로로 검증, 재설치 금지).
